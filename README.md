# Bullet in Flight

A point-mass exterior ballistics calculator. Enter a load and a sight setup; get a
range table (velocity, energy, height above/below the line of sight) and a chart of
the arc from the muzzle out to a chosen distance.

## Running it

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # solver checks against reference fixtures
```

## How the physics works

**Point-mass model.** The bullet is treated as a particle with two forces on it:
gravity and aerodynamic drag. Position and velocity are stepped forward in fixed
0.25 ms increments (forward Euler). Spin, yaw, and lift are ignored — those matter
for extreme long range, not for the ranges this tool covers.

**Drag.** Drag deceleration is

```
a = 0.0877382 * rho * v^2 * Cd(M) / BC
```

where `rho` is air density in slug/ft^3, `v` is speed in ft/s, `Cd(M)` is read from
the standard drag table by linear interpolation on Mach number, and `BC` is the
ballistic coefficient in lb/in^2. The leading constant is `0.5 * (pi/576) * 32.174`,
which folds in the circular reference area, the in^2-to-ft^2 conversion, and
pounds-mass to slugs.

**Drag tables.** `src/ballistics/dragTables.js` holds the BRL-tabulated G1 (79 points)
and G7 (84 points) Cd-vs-Mach curves. These are generated data — do not hand-edit them.
G1 is the flat-base reference; G7 is the boat-tail reference. A BC published as G1 must
be used with G1, and likewise for G7. Mixing them produces confidently wrong answers.

**Line of sight and zeroing.** The line of sight is the x-axis. The bullet starts one
sight height below it and is launched at an angle found by secant iteration so that the
trajectory crosses zero exactly at the zero range. This is why most loads show two
zeros — a near one on the way up and the nominal one on the way down — and a positive
max ordinate in between.

**Atmosphere.** Density and speed of sound come from station (absolute) pressure and
temperature. The altitude field only prefills those two values from the ICAO standard
atmosphere; it is never applied on top of a pressure the user entered. Double-counting
altitude is the most common way to get quietly wrong numbers here.

## Accuracy

`npm test` checks the solver against fixtures generated by `py-ballisticcalc`, an
independent RK4 implementation, across three cartridges (.308 175gr G7, .223 55gr G1,
6.5 140gr G7) out to 1000 yards. Current agreement:

| Check | Worst deviation |
| --- | --- |
| Zero launch angle | 0.0001 deg |
| Velocity | 0.9 fps |
| Energy | 0.7 ft-lb |
| Height | 0.11 in |
| Time of flight | 0.0004 s |

Regenerate fixtures with `test/fixtures/generate.py` if the reference solver is updated.

## Layout

```
src/
  ballistics/
    dragTables.js    generated G1/G7 Cd-vs-Mach data
    atmosphere.js    air density, speed of sound, standard atmosphere
    solver.js        integration, zeroing, sampling, Mach crossings
  components/        presentational React only, no physics
  App.jsx            state, validation, wiring
test/
  solver.test.mjs    fixture comparison
  fixtures/          reference trajectories + generator
```

Physics lives in `src/ballistics/` and knows nothing about React. Components take a
solved trajectory and render it. Keep that boundary — it is what makes the solver
testable.

## Not modeled yet

Wind deflection, spin drift, Coriolis, aerodynamic jump, and powder temperature
sensitivity. Transonic (Mach 1.2 down to 1.0) is shaded on the chart and tinted in the
table because that is where G1/G7 standard curves diverge most from a real bullet's
measured drag; treat predictions there as soft.
